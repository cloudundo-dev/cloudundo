Your agent can delete anything. You can always get it back.

cloudundo sits in front of the AWS, Terraform and CloudFormation commands that Claude Code, Cursor and Codex run. Before a command deletes your S3, DynamoDB or RDS data, it makes that data recoverable. Then one command brings it back.

How it works

The agent keeps working as usual. cloudundo only steps in when a command would destroy data, and only to make it recoverable first.

  1. The agent runs a command

    Every shell command passes through the agent's hook. cloudundo reads it, including && chains, bash -c, cd and Terraform plans. Anything that touches no data runs untouched.

  2. The data is made recoverable

    Versioning for S3 objects, a verified copy of a bucket, a backup of a table, a snapshot of a database. If any of it fails, the command does not run.

  3. You undo it

    cloudundo undo 3 shows what it would restore. --yes restores it. Undo never deletes data, so an undo can be undone too.

What it covers

Through the AWS CLI, a terraform apply / destroy, or a CloudFormation stack delete, change set or deploy. cloudundo reads the plan or the stack first, without applying anything.

What it does not do

Know where the edges are before you rely on it.

  • It is a seatbelt, not a lock.The agent still holds your AWS keys. cloudundo policy prints an IAM policy that stops those keys from deleting the backups.
  • It sees commands, not programs.A Python script, an SDK call or make destroy that deletes data is not seen.
  • Not inside the database.DROP TABLE through psql goes straight to the database. Use RDS point-in-time recovery for that.
  • AWS only, for now.Supabase, Railway, GCP and Azure are not covered yet. cdk destroy, pulumi destroy and Terragrunt are blocked, not protected.

Set up

Two lines, whatever agents you use. The second finds Claude Code, Cursor and Codex on your computer and connects each of them.

Install and connect

curl -fsSL https://raw.githubusercontent.com/cloudundo-dev/cloudundo/main/install.sh | sh
cloudundo install --write

Then start a new Claude Code session, quit and reopen Cursor, and in Codex run /hooks once to trust the hook. On Windows, run both lines inside WSL.

Your own agent

cloudundo protect -- "<the command>"

Call it before each shell command your agent runs. Exit code 0: run it. Anything else: don't. Example

AI coding agents have wiped production databases, and the snapshots meant to back them up, in seconds.

Most guardrails try to block risky commands, which slows agents down until people switch the guardrails off. cloudundo takes the other route: let the agent work, and make sure a delete can be taken back. Not only in production: staging and dev accounts hold data people need too, and agents work there all day.

It is a single program with no dependencies and no telemetry, open source under Apache 2.0, and it calls your own aws CLI with the same account and region as the agent's command. Everything it changes in your account is listed.
